Secure chat application

Networks course project · November to December 2025 · Solo

  • Java
  • Sockets
  • Threads
  • RSA
  • AES
  • Swing

Goal

Build a chat server where many clients talk in private rooms, and where the server cannot read the messages.

What I did

  • A multi-client server: one thread per connection, capped by a fixed thread pool so the server does not collapse under load.
  • Private rooms with admin rights: invite, kick, delete, promote a new admin, rename.
  • End-to-end encryption. Each room has its own AES key, sent to every member encrypted with their RSA public key (OAEP). Messages are encrypted on the client with AES-CBC and a fresh IV each time.
  • Key rotation: when someone leaves or is kicked, the room gets a new key, so former members cannot read what comes next.
  • "Never trust the client": every request is checked for syntax and for logic (does this room exist, is this user admin) before anything runs.
  • Thread-safe state with ConcurrentHashMap and AtomicInteger.
  • A Swing interface designed to be simple to use.

Result

A working encrypted chat in about 1,000 lines of Java, built over 37 commits in one month, with a written report on the security choices.

What I learnt

Security is a design decision, not a feature you add at the end. I now think about what the client is allowed to see in every API I write.

DES encryption from scratch

Networks course project · September to October 2025 · Solo

  • Java
  • Cryptography
  • JUnit 5

Goal

Implement the DES block cipher by hand, without any crypto library, to understand how a symmetric cipher really works.

What I did

  • Conversion between UTF-8 text and 64-bit blocks, with padding.
  • Initial and inverse permutations, block splitting and merging, left shifts, XOR.
  • The key schedule: a random 64-bit master key turned into 16 round keys with PC-1 and PC-2.
  • The F function with expansion, the 8 S-boxes and the P permutation.
  • Encryption and decryption over the full 16 rounds.
  • I wrote a test for each step as I built it: 38 JUnit 5 tests in total.

Result

A text goes in, gets encrypted, and comes back out identical after decryption. Every building block is documented with Javadoc and covered by tests.

What I learnt

Testing each small piece first made the full cipher much easier to debug. It also showed me why real projects should never roll their own crypto.

The source code of both projects is in private repositories, available on request.
